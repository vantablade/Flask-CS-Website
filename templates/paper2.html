What the exam looks like

You're given a question paper and a folder of starter files: partly written Python programs and sometimes data files (such as .txt or .csv). You open them in your IDE, write or fix the code, and save your work. Your saved code files are what get marked.

It mainly assesses Topic 1 (Problem solving) and Topic 2 (Programming) of the specification. Typical task types:

Task typeWhat you doPractise in
Find and fixCorrect the syntax, runtime and logic errors in a given programErrors
Complete the codeFill in missing lines or parts of lines in a partly written programAll topics
Rearrange / amendPut lines of code in the right order, or improve existing codeReadable code
Write from scratchDesign and code a whole solution from a written scenario, often with validation, files, lists and subprogramsValidation, Files
AlgorithmsImplement or adapt a search or sortAlgorithms

How marks are earned

  • Functionality: does the program do what the question asks, for all inputs?
  • Use of the right constructs: loops, selection, subprograms and data structures where they make sense.
  • Readability and maintainability: comments, meaningful names, sensible layout. In longer programs these carry marks of their own.
  • Robustness: validating input so the program doesn't crash on bad data.

Partial solutions earn partial marks. A program that does most of the task scores far better than a blank file.

The Programming Language Subset (PLS)

Pearson publishes a Programming Language Subset document that lists the Python features you're expected to know. Starter code in the exam uses those features, so get to know the PLS well. The essentials:

Basics

print() input() int() float() str() bool() round() len() type()

Operators

+ - * / // % ** == != < <= > >= and or not

Control

if elif else for … in range() while def return

Lists

append() insert() pop() remove() in len() list[i][j]

Strings

upper() lower() find() index() split() strip() isdigit() isalpha() ord() chr() [a:b]

Files & libraries

open() read() readline() write() close() with random math time

Exam technique

  1. Read the whole question first. Underline the inputs, the outputs and any rules (e.g. "must use a subprogram", "do not use built-in sort").
  2. Run the starter code before changing it so you know what it does now.
  3. Build in small steps. Write a few lines, run them, then continue. Don't type 50 lines and hope.
  4. Save often under the exact filename asked for.
  5. Test with normal, boundary and erroneous data and compare against what you'd expect.
  6. Match the output format in the question exactly (words, spacing, units, decimal places).
  7. Leave time to tidy up: add comments and rename unclear variables.
  8. Never leave a question blank. Comments describing your plan, or partial code, can still earn marks.
